# Release Notes — v1.0.0

**Project:** Raspberry Pi 5 Custom Embedded Linux BSP  
**Release:** `v1.0.0`  
**Release Type:** Initial stable platform release

---

## Overview

`v1.0.0` is the first stable release of the Raspberry Pi 5 Custom Embedded
Linux BSP platform.

This release establishes a reproducible Embedded Linux platform consisting of:

- Fixed AArch64 SDK/toolchain and sysroot
- Raspberry Pi downstream Linux kernel
- PREEMPT_RT kernel configuration
- Device Tree and overlays
- BusyBox-based userspace
- Dropbear SSH
- Linux `rt-tests`
- Runtime dependency resolution
- Custom initramfs
- Raspberry Pi boot filesystem
- Automated bootable image generation

The primary goal of this release is to provide a working, reproducible BSP
foundation that can be extended with additional kernel drivers, Device Tree
changes and product-specific hardware support.

---

# 1. Major Features

## 1.1 Custom Raspberry Pi 5 Linux BSP

The platform is built around the Raspberry Pi downstream Linux kernel rather
than treating the target as a generic ARM64 Linux system.

The BSP layer includes:

```text
Raspberry Pi Linux kernel
        │
        ├── Kernel configuration
        ├── PREEMPT_RT
        ├── Device Tree
        ├── DT overlays
        └── Hardware-specific configuration
```

---

## 1.2 Fixed SDK / Sysroot

Userspace packages are built using a fixed target SDK and sysroot.

The build pipeline exports:

```text
SYSROOT
CROSS_COMPILE
```

This provides a stable userspace ABI/build environment while allowing the
kernel/BSP layer to evolve independently.

---

## 1.3 BusyBox Userspace

BusyBox provides the core minimal userspace and early boot environment.

BusyBox is built statically so that the early userspace does not depend on
the dynamic loader.

The system includes core utilities and the BusyBox shell/init environment.

---

## 1.4 Dropbear SSH

Dropbear is integrated as the lightweight SSH server for remote access to
the target Raspberry Pi 5 system.

---

## 1.5 Linux Real-Time Tests

`rt-tests` is integrated into the root filesystem.

The release supports running:

```bash
cyclictest
```

for real-time latency evaluation with the PREEMPT_RT kernel.

# 2. Important Fixes

## 2.1 Kernel Page-Alignment Compatibility Investigation

An early boot/runtime failure was investigated at the ELF/kernel page-size
boundary.

The investigation verified the actual `LOAD` segment alignment of target
ELF binaries using:

```bash
readelf -l
```

The tested SDK binaries use alignment compatible with page sizes of:

```text
16 KB
64 KB
```

while the tested 4-KB page-size configuration was incompatible.

The important conclusion from the investigation was that the issue was not
simply a generic "64-KB-only" requirement.

The ELF `LOAD` alignment is rounded according to the maximum segment size and
the resulting binaries are compatible with page sizes greater than or equal
to the required alignment.

Detailed investigation records are maintained under:

```text
docs/
```

---

## 2.2 Dynamic Loader / Runtime Library Fix

A separate userspace boot/runtime failure was traced to the dynamic loader
not finding dependencies installed under `/usr/lib`.

The minimal system uses both:

```text
/lib
/usr/lib
```

The startup environment therefore configures:

```sh
export LD_LIBRARY_PATH=/lib:/usr/lib
```

This allows dynamically linked applications such as `cyclictest` to locate
their required runtime libraries.

The dependency-resolution stage also installs required shared libraries
into the target root filesystem.

---

## 2.3 Static BusyBox

BusyBox is built statically because it is responsible for early userspace,
including the shell and init environment.

This prevents the early boot environment from depending on the dynamic
loader and its shared-library dependency chain.

# 3. RootFS Build Pipeline

A reusable build pipeline was added:

```text
scripts/build_rootfs_pipeline.sh
```

The pipeline performs the major userspace build stages:

```text
SDK setup
    ↓
BusyBox
    ↓
ELF/page-size validation
    ↓
Dropbear
    ↓
rt-tests
    ↓
Safe rootfs cleanup
    ↓
RootFS construction
    ↓
Runtime dependency resolution
    ↓
Banner installation
    ↓
rpi_bootfs
    ↓
Optional bootable image
```

A normal rootfs build:

```bash
./scripts/build_rootfs_pipeline.sh custom-sdk
```

A complete rootfs + bootable image build:

```bash
./scripts/build_rootfs_pipeline.sh custom-sdk --bootable
```

# 4. Bootable Image Generation

An independent image-generation library was added:

```text
lib/rpi5_image.sh
```

It creates:

```text
Bootable/rpi5_custom.img
```

The generated image contains:

```text
MBR / DOS partition table
        │
        └── FAT32 boot partition
                │
                ├── Kernel
                ├── DTB
                ├── DT overlays
                ├── config.txt
                ├── cmdline.txt
                └── rootfs.cpio.gz
```

The image-generation flow is:

```text
Create image
    ↓
Create MBR partition table
    ↓
Create FAT32 partition
    ↓
Attach loop device
    ↓
Format FAT32
    ↓
Mount partition
    ↓
Copy rpi_bootfs
    ↓
sync
    ↓
Verify
    ↓
Unmount
    ↓
Detach loop device
```

The image generator can also be executed independently:

```bash
./lib/rpi5_image.sh
```

This allows image regeneration without rebuilding the entire root filesystem.

# 5. Custom System Banner

The system banner is maintained as a source-controlled project artifact:

```text
lib/banner
```

It is installed into the target root filesystem as:

```text
/usr/bin/banner
```

BusyBox init executes it through:

```text
::once:/usr/bin/banner
```

This prevents the banner customization from being lost when the generated
root filesystem is rebuilt.
